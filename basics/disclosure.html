2.5 Tabs / Accordion：内容组织原语 ​

漫画引入 ​

小 R：设置页有 8 个分区，我全堆在一页，用户滚到怀疑人生。

老 S：平级视图用 Tabs，逐条展开用 Accordion。它们都只给结构与键盘行为，外观你说了算。

小 R：那用 Tabs 还是 Accordion 有什么硬标准？

老 S：同一时刻只想看一个面板 → Tabs；希望用户按需展开多条 → Accordion。别用 Accordion 藏关键操作。

学习目标 ​

  • 掌握 Tabs 的组合结构、受控模式、方向与线型变体。
  • 理解 roving tabindex 与方向键切换的键盘模型。
  • 掌握 Accordion 的 single / multiple、collapsible 与受控用法。
  • 知道内容挂载策略（默认卸载 vs forceMount）对性能与状态的影响。

概念讲解 ​

Tabs 的三件套 ​

tsx
<Tabs defaultValue="overview">
  <TabsList>
    <TabsTrigger value="overview">概览</TabsTrigger>
    <TabsTrigger value="docs">文档</TabsTrigger>
    <TabsTrigger value="settings">设置</TabsTrigger>
  </TabsList>
  <TabsContent value="overview">...</TabsContent>
  <TabsContent value="docs">...</TabsContent>
  <TabsContent value="settings">...</TabsContent>
</Tabs>
  • Tabs 管理选中值；defaultValue 用于非受控，value + onValueChange 用于受控。
  • TabsList 承载键盘焦点：只有当前触发器 tabIndex=0，其余为 -1（roving tabindex）。按左右方向键时由 Radix 移动焦点并激活对应面板。
  • TabsContent 默认只挂载当前激活项；切走后面板卸载，内部表单状态会丢失。

受控 Tabs：把状态放到 URL 或全局 ​

tsx
const [tab, setTab] = useState('overview')

<Tabs value={tab} onValueChange={setTab}>
  {/* ... */}
</Tabs>

受控后可以做这些事：

  • 与 URL 查询参数同步（?tab=docs），刷新后保持视图；
  • 在切换前做拦截（例如「有未保存修改，确认离开？」）；
  • 根据权限动态禁用某些 TabsTrigger（用 disabled）。

方向与线型变体 ​

tsx
<Tabs orientation="vertical">          {/* 纵向：方向键改为上下 */}
  <TabsList variant="line">           {/* 去掉灰底，适合页面级导航 */}
    <TabsTrigger value="a">A</TabsTrigger>
  </TabsList>
</Tabs>

orientation 会同时影响布局与键盘方向，二者不要分开手写。variant="line" 用下划线指示选中项，适合内容区顶部的分区导航。

内容挂载策略 ​

策略行为适用
默认非激活面板卸载面板较重、希望省内存
forceMount始终挂载，仅隐藏需要保留滚动位置、表单草稿、图表实例
tsx
<TabsContent value="chart" forceMount className="data-[state=inactive]:hidden">
  <HeavyChart />
</TabsContent>

注意：forceMount 后需要自己处理隐藏（data-[state=inactive]:hidden），否则多个面板会叠在一起。

Accordion：单开与多开 ​

tsx
{/* 同一时刻只展开一项，允许全部收起 */}
<Accordion type="single" collapsible defaultValue="item-1">
  <AccordionItem value="item-1">
    <AccordionTrigger>问题一</AccordionTrigger>
    <AccordionContent>回答一</AccordionContent>
  </AccordionItem>
</Accordion>

{/* 多开：适合设置分组 */}
<Accordion type="multiple" defaultValue={['a', 'b']}>
  {/* ... */}
</Accordion>
  • type 是必填项。single 不传 collapsible 时，用户无法收起当前项。
  • AccordionTrigger 内部已包好 <h3> 与按钮结构，并自动切换 Chevron 图标。
  • 展开动画的高度来自 Radix 写入的 CSS 变量 --radix-accordion-content-height，组件源码用 data-open:animate-accordion-down 驱动，不需要你测高度。

受控 Accordion ​

tsx
const [open, setOpen] = useState<string[]>(['shipping'])

<Accordion type="multiple" value={open} onValueChange={setOpen}>
  {/* ... */}
</Accordion>

受控后可以做「展开第二项时收起第一项」「根据搜索结果自动展开命中项」等业务逻辑。

语义与 SEO ​

  • Tabs 的每个触发器都有 role="tab"、aria-selected、aria-controls；面板有 role="tabpanel"。
  • Accordion 的触发器是 <button>，标题在 <h3> 里，读屏器能按标题层级跳转。
  • 两种组件默认只渲染激活内容。对 SEO 重要的正文不要只放在非默认 Tab 里；必要时用 forceMount 或改成独立页面。

可运行示例 ​

完整工程见 examples/07-disclosure。

bash
cd examples/07-disclosure
pnpm install
pnpm dev

页面包含：

  1. 受控 Tabs 工作台：概览 / 文档 / 设置，标题上方实时显示当前值。
  2. 线型变体 Tabs：安装 / 使用 / 常见问题。
  3. Accordion FAQ：type="single" + collapsible，默认展开第一条。

关键代码：

tsx
<Tabs value={tab} onValueChange={setTab}>
  <TabsList>
    <TabsTrigger value="overview"><LayoutDashboard />概览</TabsTrigger>
    <TabsTrigger value="docs"><FileText />文档</TabsTrigger>
  </TabsList>
  <TabsContent value="overview">...</TabsContent>
  <TabsContent value="docs">...</TabsContent>
</Tabs>

验证重点：

  • 用 Tab 进入 TabsList，只停在一个触发器上；按左右方向键切换面板。
  • 切换回「概览」时，当前视图 文本同步变化（受控）。
  • Accordion 同一时刻只展开一条；再次点击已展开项可全部收起（collapsible）。
  • 用键盘 ↑ / ↓ 在 Accordion 标题间移动，Enter 展开。

常见坑 FAQ ​

Q：Tabs 内容切换后表单内容丢了？

默认非激活面板会卸载。需要保留状态时用 forceMount + 隐藏，或把状态提升到父组件 / 全局 store。

Q：为什么方向键没反应？

焦点必须先在 TabsList 内（按一次 Tab 进入）。若你给 TabsTrigger 手动加了 tabIndex，会破坏 roving tabindex。

Q：Accordion 收起后再展开，内部组件重新挂载？

是的，默认会卸载内容。需要保活时用受控 value 并让内容常驻，或改用 Tabs + forceMount。

Q：能在 Accordion 标题里放按钮吗？

不要。AccordionTrigger 本身是按钮，嵌套交互元素会破坏键盘与读屏语义。把操作放到展开内容里。

Q：Tabs 想做成路由驱动怎么办？

把 value 绑定到当前路由参数，onValueChange 里调用导航。注意保持浏览器前进/后退与 Tabs 状态一致。

练习与延伸 ​

  1. 把示例中的受控 Tabs 与 URL 查询参数同步（用 URLSearchParams + history.replaceState）。
  2. 给 Accordion 增加「全部展开 / 全部收起」按钮。
  3. 用 forceMount 保留一个带输入框的 Tab 面板，验证切换后草稿还在。
  4. 阅读 Radix Tabs 的 Keyboard Interactions 表格。
  5. 阶段小结：现在你已经掌握 Radix 核心原语与 Tailwind 样式体系，可以进入进阶篇，学习 CLI 工作流、主题定制与业务组件封装。
