2.2 设计 token 与 dark mode ​

漫画引入 ​

小 R：我想加暗色模式，难道要给每个组件再写一套 dark:bg-slate-900？

老 S：那是补丁式做法。正确姿势是让组件只认语义 token——bg-background、text-foreground，暗色只是换一组变量值。

小 R：所以组件代码一行都不用改？

老 S：一行都不用改。你只需要在 <html> 上切换一个 dark 类。

学习目标 ​

  • 理解 :root / .dark 两组 CSS variables 如何驱动整站主题。
  • 看懂 @theme inline 把变量映射成 Tailwind 工具类的过程。
  • 实现「跟随系统 + 用户选择 + 本地持久化」的暗色模式，并消除闪白。
  • 能为团队新增自定义 token（品牌色、图表色、圆角）。

概念讲解 ​

token 的三层结构 ​

以背景色为例：

css
/* 1. 原始变量：定义两套值 */
:root { --background: oklch(1 0 0); }
.dark { --background: oklch(0.145 0 0); }

/* 2. 映射：让 Tailwind 认识 bg-background */
@theme inline {
  --color-background: var(--background);
}

/* 3. 使用：组件里只写语义类名 */
<div className="bg-background text-foreground" />

@theme inline 的关键是 inline：生成工具类时直接引用 var(--background)，而不是在 @theme 里固化一份值。这样 .dark 改变量后，所有 bg-background 立即生效。

语义 token 清单 ​

shadcn 预设提供了一套完整语义层：

token用途
background / foreground页面底色与主文字
card / card-foreground卡片容器
popover / popover-foreground浮层容器
primary / primary-foreground主操作
secondary / secondary-foreground次操作
muted / muted-foreground弱化背景与辅助文字
accent / accent-foreground悬停、选中态
destructive危险操作
border / input / ring描边、表单边框、焦点环
chart-1..5图表色板
sidebar-*侧边栏专用

命名规律：成对出现（背景 + 前景），保证对比度由 token 负责，而不是每个组件各自猜。

圆角与字体同样是 token ​

css
:root { --radius: 0.625rem; }

@theme inline {
  --radius-sm: calc(var(--radius) * 0.6);
  --radius-md: calc(var(--radius) * 0.8);
  --radius-lg: var(--radius);
  --radius-xl: calc(var(--radius) * 1.4);
}

只改 --radius 一处，整站圆角按比例联动。字体同理：--font-sans 映射到 font-sans，--font-heading 映射到 font-heading。

暗色策略：class 而不是 media ​

shadcn 在 CSS 里声明：

css
@custom-variant dark (&:is(.dark *));

这行的意思是：dark: 变体在「祖先带 .dark」时生效。于是：

  • 用户在界面上点切换 → 给 document.documentElement 加/删 dark；
  • 首次访问 → 读 localStorage，没有则读 prefers-color-scheme；
  • 服务端渲染 → 可以用 cookie 传递，避免水合闪烁。

如果直接用 Tailwind v4 默认的 dark:（跟随 prefers-color-scheme），用户就无法手动覆盖系统设置。三态需求必须用 class 策略。

消除闪白（FOUC） ​

React 挂载前页面已经绘制了一帧。若暗色用户先看到白底，体验会很差。在 index.html 的 <head> 里放一段内联脚本：

html
<script>
  ;(() => {
    const stored = localStorage.getItem('theme')
    const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches
    const dark = stored ? stored === 'dark' : prefersDark
    document.documentElement.classList.toggle('dark', dark)
    document.documentElement.style.colorScheme = dark ? 'dark' : 'light'
  })()
</script>

colorScheme 同步给浏览器原生控件（滚动条、输入框、日期选择器），否则暗色页面里会出现白色滚动条。

切换组件 ​

tsx
const [theme, setTheme] = useState<Theme>(getInitialTheme)

useEffect(() => {
  const root = document.documentElement
  root.classList.toggle('dark', theme === 'dark')
  root.style.colorScheme = theme
  localStorage.setItem('theme', theme)
}, [theme])

getInitialTheme 从 DOM 读取内联脚本已经设置好的结果，保证 React 状态与页面一致。

可运行示例 ​

完整工程见 examples/04-dark-mode。

bash
cd examples/04-dark-mode
pnpm install
pnpm dev

页面包含：

  1. 右上角切换按钮（ThemeToggle）。
  2. 语义 token 色板，切换主题时同屏对比。
  3. Button / Card 组件，代码里没有任何 dark: 类名。
  4. 圆角 token 阶梯。
  5. index.html 的内联防闪脚本。

验证清单：

  • 首次打开跟随系统深色设置；
  • 点击切换后刷新页面，选择被记住；
  • 切换时观察滚动条颜色同步变化；
  • 在 DevTools 里给 <html> 手动加 dark，整页立即换肤。

常见坑 FAQ ​

Q：为什么我写了 dark:bg-slate-900 却不生效？

检查组件的祖先链上是否有 .dark。若你用的是纯 Tailwind 工程（没有 shadcn 的 @custom-variant），dark: 默认跟随系统媒体查询，手动加 class 不起作用。

Q：@theme 和 @theme inline 有什么区别？

普通 @theme 会把值固化进生成的 CSS；inline 则引用 var(...)，适合需要运行时切换的主题变量。

Q：为什么不把两套颜色直接写进组件？

组件会感知主题，主题逻辑会散落在几十个文件里。token 方案把「换肤」收敛到一个 CSS 文件。

Q：SSR 下怎么避免闪烁？

把用户选择写进 cookie，服务端渲染时给 <html> 输出对应 class。纯 Vite SPA 用内联脚本即可。

Q：暗色下对比度不够怎么办？

先检查是否用了原始色阶（如 text-slate-500）而不是 text-muted-foreground。shadcn 预设的 muted-foreground 在暗色下会换成更亮的值；自定义 token 时用 APCA 或 WCAG 对比度工具 验证。

练习与延伸 ​

  1. 新增 --color-brand 与 --color-brand-foreground，在亮/暗两套变量里各给一组值，并做一个 bg-brand 徽标。
  2. 把切换组件扩展为「浅色 / 深色 / 跟随系统」三态，用 matchMedia('(prefers-color-scheme: dark)') 监听系统变化。
  3. 用 @media (prefers-reduced-motion: reduce) 关掉过渡动画。
