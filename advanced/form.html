3.4 表单体系：React Hook Form + Zod ​

漫画引入 ​

小 R：我给表单写了 12 个 useState，每个字段还要手写 errors.xxx，现在要加一个「确认密码」……

老 S：你缺的不是毅力，是分层。状态归 React Hook Form，规则归 Zod，布局归 Field。

小 R：那服务端返回「邮箱已存在」怎么办？

老 S：setError('email', ...) 回填到同一个错误槽，UI 不用分叉。

学习目标 ​

  • 用 Zod 定义一份可复用的校验 schema，并从 schema 推导 TS 类型。
  • 用 useForm 管理值、错误、提交状态，理解 mode 对体验的影响。
  • 用 Controller 接入 Select、Checkbox 等非原生输入。
  • 用 Field 系列组件组织标签、描述与错误，保持无障碍。
  • 处理服务端错误与异步提交。

概念讲解 ​

职责划分 ​

text
Zod          → 什么算合法（纯函数，可单测、可共享）
React Hook Form → 当前值、哪个字段错了、是否在提交
Field        → 标签、描述、错误放在哪，aria 关系怎么连

三者解耦后，schema 可以给前端、后端、表单三处复用。

schema 与类型 ​

ts
const schema = z.object({
  name: z.string().min(2, '姓名至少 2 个字符'),
  email: z.string().email('请输入有效的邮箱地址'),
  role: z.enum(['viewer', 'editor', 'admin'], { message: '请选择成员角色' }),
  bio: z.string().max(120, '简介最多 120 个字').optional(),
  agree: z.boolean().refine((v) => v, '请先阅读并同意协作规范'),
})

type FormValues = z.infer<typeof schema>

从 schema 推导类型，避免「类型与规则各写一份，改了一边忘了另一边」。

useForm 的关键配置 ​

tsx
const form = useForm<FormValues>({
  resolver: zodResolver(schema),
  defaultValues: { name: '', email: '', role: 'editor', bio: '', agree: false },
  mode: 'onBlur',
})
  • defaultValues 必须给全。缺字段会让受控组件在首渲染时变成非受控。
  • mode: 'onBlur'：字段失焦才校验，避免边输入边报红。
  • reValidateMode: 'onChange'（默认）：一旦出错，后续输入实时复检，错误能及时消失。

原生输入用 register ​

tsx
<Input id="name" {...form.register('name')} />

register 返回 name / onChange / onBlur / ref，直接展开即可。配合 Field 时手动补 aria-invalid：

tsx
<Field data-invalid={Boolean(form.formState.errors.name)}>
  <FieldLabel htmlFor="name">姓名</FieldLabel>
  <Input id="name" aria-invalid={Boolean(form.formState.errors.name)} {...form.register('name')} />
  <FieldError errors={[form.formState.errors.name]} />
</Field>

非原生输入用 Controller ​

Select、Checkbox、日期选择器不会触发原生 onChange 事件，必须用 Controller 把 field.value / field.onChange 接进去：

tsx
<Controller
  control={form.control}
  name="role"
  render={({ field, fieldState }) => (
    <Field data-invalid={fieldState.invalid}>
      <FieldLabel htmlFor="role">角色</FieldLabel>
      <Select value={field.value} onValueChange={field.onChange}>
        <SelectTrigger id="role" aria-invalid={fieldState.invalid}>
          <SelectValue />
        </SelectTrigger>
        <SelectContent>...</SelectContent>
      </Select>
      <FieldError errors={[fieldState.error]} />
    </Field>
  )}
/>

Checkbox 的 onCheckedChange 给的是 boolean | 'indeterminate'，记得归一化：

tsx
onCheckedChange={(checked) => field.onChange(checked === true)}

服务端错误回填 ​

tsx
if (values.email === 'taken@example.com') {
  form.setError('email', { message: '该邮箱已被团队成员使用' })
  return
}

setError 写入的是同一套 formState.errors，所以 FieldError 不需要区分「前端错误」与「后端错误」。跨字段错误用 setError('root.serverError', ...)。

提交与重置 ​

tsx
<form onSubmit={form.handleSubmit(onSubmit)} noValidate>
  • 加 noValidate 关掉浏览器原生气泡，保证错误展示只有一套。
  • formState.isSubmitting 驱动按钮加载态，避免重复提交。
  • form.reset(defaultValues) 同时清空值与错误。

大表单的性能 ​

RHF 默认非受控，字段变化不会重渲染整个表单。但 form.watch('bio') 会让订阅该值的组件重渲染——只在你需要实时字数、联动时使用。字段很多时，用 useWatch({ control, name }) 把订阅下沉到子组件。

常见坑 FAQ ​

Q：zodResolver 类型报错，提示 resolver 不匹配？

先确认 zod、@hookform/resolvers、react-hook-form 三者版本兼容。Zod 4 需要 @hookform/resolvers v6 及以上。

Q：输入框第一下输入没反应？

defaultValues 缺了这个字段，组件从非受控切到受控。补齐默认值即可。

Q：错误信息一直不消失？

检查 mode 与 reValidateMode。mode: 'onBlur' 下，错误要在字段再次失焦后才复检；如果希望输入即复检，把 reValidateMode 设为 'onChange'（默认就是）。

Q：Select 选完值，提交却是空？

忘了用 Controller，或 onValueChange 没接 field.onChange，只改了本地 state。

Q：怎么处理「两次密码不一致」？

在 schema 里用 .refine((data) => data.password === data.confirm, { path: ['confirm'], message: '两次输入不一致' })，错误会自动落到 confirm 字段。

Q：需要动态字段数组怎么办？

用 useFieldArray。每行一个 Controller 或 register(\items.${index}.name`)，删除时调用 remove(index)`。
