3.1 shadcn/ui CLI 工作流 ​

漫画引入 ​

小 R：我把 button.tsx 改得面目全非，结果同事一条 shadcn add button --overwrite 全给我冲掉了。

老 S：CLI 不认识你的业务，它只按 registry 覆盖文件。所以约定是：先 commit，再 overwrite，diff 看完再决定。

小 R：那为什么还要用 CLI？直接复制官网代码不行吗？

老 S：官网代码没有你的别名、没有你的 token、也不会帮你补依赖。CLI 的价值是「按项目配置正确地复制」。

学习目标 ​

  • 说清 shadcn/ui 与传统组件库的本质差异：源码复制 vs 运行时依赖。
  • 掌握 init / add / diff / view 四个命令的适用场景。
  • 能读懂 components.json 的每一项，并知道改错之后会出什么问题。
  • 建立团队协作约定：什么时候覆盖、什么时候保留本地改动。

概念讲解 ​

不是依赖，是流水线 ​

传统组件库：pnpm add @acme/ui，组件在 node_modules 里，你只能通过 props 和 CSS 覆盖来定制。

shadcn/ui：CLI 把组件源码写进 src/components/ui/，它成为你项目的一部分。

维度npm 组件库shadcn/ui
代码位置node_modules你的 src/
定制方式props / CSS 覆盖 / patch直接改源码
升级方式整包升级add --overwrite 或手动 diff
体积引了就可能全进包删文件即删除
责任库作者你自己

这也解释了为什么 shadcn 文档反复强调「You own the code」。

init 做了什么 ​

bash
pnpm dlx shadcn@latest init -b radix -p nova

三个产物：

  1. components.json：项目级配置，后续所有命令都读它。
  2. src/lib/utils.ts：cn()，由 clsx + tailwind-merge 组成，负责类名条件拼接与冲突消解。
  3. src/index.css：@theme inline 映射与 :root / .dark 的 CSS 变量。

-b radix 指定底层原语来自 Radix，-p nova 指定预设风格。不同预设主要差异在圆角、密度与默认配色，源码结构一致。

components.json 逐项说明 ​

json
{
  "style": "radix-nova",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/index.css",
    "baseColor": "neutral",
    "cssVariables": true
  },
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  },
  "iconLibrary": "lucide",
  "registries": {}
}
  • tailwind.config 为空是 v4 的正常状态：配置在 CSS 里。
  • tailwind.css 指向的必须是引入 Tailwind 的那份 CSS，否则 add 找不到 token。
  • aliases.ui 决定源码落盘目录，也决定组件之间的相对导入写法。
  • aliases.utils 是组件源码里 import { cn } from "@/lib/utils" 的来源。
  • registries 预留给私有 registry：团队可以把内部组件发布成 registry，继续用同一套 CLI。

add 的几种形态 ​

bash
# 一次加多个
pnpm dlx shadcn@latest add button card dialog

# 覆盖本地版本（先 commit！）
pnpm dlx shadcn@latest add button --overwrite

# 只看 registry 里的源码，不落盘
pnpm dlx shadcn@latest view button

# 对比本地与 registry 的差异
pnpm dlx shadcn@latest diff button

add 还会自动补依赖。例如添加 dialog 会安装 radix-ui，添加 form 相关组件会提示安装 react-hook-form 与 zod（新版本中表单布局已迁移到 field）。

<div className="flex flex-wrap gap-2">

常见坑 FAQ ​

Q：add 报错 "Invalid registry namespace"？

你执行的可能是 search form 这类旧命令。4.x 的 search 需要命名空间（如 @shadcn），而 add / view / diff 直接接受组件名。

Q：组件加进来了，但 import 报找不到 @/lib/utils？

检查 tsconfig.json 的 paths 与 vite.config.ts 的 resolve.alias 是否同时配置。CLI 只写文件，不会替你补构建配置。

Q：components.json 里 style 改成别的，会迁移已有组件吗？

不会。style 只影响之后 add 生成的源码。已有组件需要重新 add 或手动迁移。

Q：能不能把 ui 目录改成 src/ui？

可以，改 aliases.ui 后重新 add。但已有文件的相对导入不会自动改，需要一次性全局替换。

Q：团队里有人手动改了组件，升级时怎么办？

把「本地改动」视为 fork。升级时先 diff，逐段合并；不要直接 --overwrite。改动较大的组件，建议在业务层再包一层，而不是改原语。

Q：为什么示例里每个 example 都有 pnpm-workspace.yaml？

pnpm 12 要求把依赖构建脚本的批准写进 workspace 配置。每个示例作为独立根，避免被仓库根目录的文档工程接管。
