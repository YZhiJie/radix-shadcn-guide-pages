1.1 生态关系辨析：Radix、shadcn/ui、Tailwind 各管什么 ​

漫画引入 ​

小 R：我在网上看到三个名字——Radix UI、shadcn/ui、Tailwind CSS。它们是一个东西的三个叫法吗？

老 S：不是。把它们想成「骨架」「皮肤」和「装修图纸」：Radix 提供行为与无障碍，Tailwind 提供样式词汇，shadcn/ui 把两者拼成可以直接改的成品组件。

小 R：那 shadcn/ui 是不是一个 npm 组件库？pnpm add 一下就能用？

老 S：恰恰相反——它不是运行时的库，而是一套「把源码复制进你项目」的工作流。复制完，代码归你所有。

学习目标 ​

  • 说清 Radix UI、Tailwind CSS、shadcn/ui 各自的职责边界。
  • 理解「无样式原语 + 工具类样式 + 源码复制」这套组合为什么流行。
  • 知道 2026 年这套技术栈的版本形态：Tailwind v4、shadcn CLI 4.x、统一的 radix-ui 包。
  • 能判断一个需求该找 Radix 原语、改 shadcn 源码，还是只写 Tailwind 工具类。

概念讲解 ​

三层分工 ​

层角色负责不负责
Radix UI行为层焦点管理、键盘交互、ARIA 属性、浮层定位、状态机任何视觉样式
Tailwind CSS样式层间距、颜色、排版、响应式、状态变体组件行为与结构
shadcn/ui组装层把 Radix 原语 + Tailwind 类封装成可读、可改的组件源码版本升级、运行时依赖

这三个东西可以单独使用：

  • 只用 Tailwind：写静态页面、营销页，完全够用。
  • 只用 Radix：你有自己的 CSS 方案（CSS Modules、vanilla-extract），仍然能获得无障碍行为。
  • 只用 shadcn/ui：它本身就依赖上面两者，不能脱离它们运行。

Radix UI：把「难写对的部分」做成原语 ​

一个 Dialog 真正难的不是画一个白框，而是：

  • 打开时把焦点移进弹窗，关闭后还给触发按钮；
  • 把 Tab 键限制在弹窗内，不让焦点跑到背后的页面；
  • 处理 Esc、遮罩点击、滚动锁定；
  • 给标题、描述、关闭按钮挂上正确的 aria-* 与 role。

Radix 的每个组件都是「无样式原语」：只给结构与行为，DOM 上不写颜色和间距。你可以用任何方式给它加样式。

Tailwind CSS：受约束的样式词汇表 ​

Tailwind 把 CSS 拆成原子类：flex、gap-4、rounded-lg、text-muted-foreground。它的价值不在「少写 CSS 文件」，而在：

  1. 约束：间距、颜色、字号都来自一套标尺，团队不容易各写各的像素值。
  2. 就地修改：样式和结构在同一个文件里，改组件不用跳两个文件。
  3. 状态即类名：hover:、focus-visible:、data-open:、group-hover: 直接表达状态。

Tailwind v4 不再需要 tailwind.config.js，改用 CSS 里的 @theme 定义 token，构建由 @tailwindcss/vite 插件完成。

shadcn/ui：源码复制的组件层 ​

shadcn/ui 的 CLI 做三件事：

  1. 按 components.json 的配置（基座、别名、CSS 变量）生成组件源码到 src/components/ui/；
  2. 补齐依赖（radix-ui、class-variance-authority、cn 等）；
  3. 把设计 token 写进你的 src/index.css。

之后这些 .tsx 文件就是你的业务代码。想改圆角、改间距、加业务属性，直接改，不需要 !important 覆盖，也不会有「库升级把我样式冲掉」的问题。

看教程先看年份

网上大量 shadcn 教程停留在 2.x/3.x。思路（复制源码、Radix 行为、Tailwind 样式）完全一致，但包名、配置文件、CSS 入口都变了。遇到 @radix-ui/react-* 逐个安装的写法，要知道那是旧版。

可运行示例 ​

示例 examples/01-hello 刻意不使用 shadcn/ui：它只有 Tailwind 和一个 Radix Dialog，用来观察「行为」和「样式」如何分离。

关键代码（examples/01-hello/src/App.tsx）：

tsx
import * as Dialog from '@radix-ui/react-dialog'

<Dialog.Root>
  <Dialog.Trigger asChild>
    <button className="rounded-lg bg-slate-900 px-4 py-2 text-sm text-white">
      打开原生 Dialog
    </button>
  </Dialog.Trigger>
  <Dialog.Portal>
    <Dialog.Overlay className="fixed inset-0 bg-black/40" />
    <Dialog.Content className="fixed left-1/2 top-1/2 w-[90vw] max-w-md -translate-x-1/2 -translate-y-1/2 rounded-xl bg-white p-6">
      <Dialog.Title>无样式的弹窗</Dialog.Title>
      <Dialog.Description>焦点、键盘与 ARIA 都来自 Radix。</Dialog.Description>
      <Dialog.Close asChild>
        <button className="mt-6 rounded-lg border px-4 py-2">关闭</button>
      </Dialog.Close>
    </Dialog.Content>
  </Dialog.Portal>
</Dialog.Root>

运行：

bash
cd examples/01-hello
pnpm install
pnpm dev

验证三件事：

  1. 打开弹窗后按 Tab，焦点只在弹窗内的可聚焦元素之间循环。
  2. 按 Esc 或点遮罩，弹窗关闭，焦点回到「打开原生 Dialog」按钮。
  3. 遮罩、圆角、间距全部来自 className，Radix 没有注入任何样式。

对照示例 examples/02-first-page：同样的行为，外观被 shadcn/ui 预置成一套设计系统。

常见坑 FAQ ​

Q：shadcn/ui 能不能像 Ant Design 一样 npm install 后统一升级？

不能，也不该期待。它的定位是「源码分发」：你复制的是起点，不是受控依赖。升级方式是重新跑 CLI 对比 diff，人工合并。

Q：不用 Tailwind，能用 shadcn/ui 吗？

可以运行，但失去大部分价值。shadcn 组件的类名就是 Tailwind 工具类；你要么保留 Tailwind，要么把每个组件翻译成自己的 CSS 方案。

Q：Radix 和 Headless UI 怎么选？

两者都提供无样式行为。Radix 原语覆盖面更广（菜单、选择器、表单控件、Toast 等），并且 shadcn/ui 生态默认基于它。已有 Headless UI 技术栈的项目没必要迁移。

Q：既然 Radix 无样式，为什么还要 shadcn/ui？

Radix 只解决行为，你还得为每个原语写一套外观与组合 API。shadcn/ui 把这层重复劳动变成了可复制的模板，并且允许你继续改。
