1.2 环境搭建：Vite 6 + React 19 + Tailwind v4 ​

漫画引入 ​

小 R：我照着一篇 2023 年的教程装了半天，tailwind.config.js 死活不生效，npx shadcn-ui 也报错。

老 S：教程过期了。Tailwind v4 已经没有配置文件，shadcn CLI 也换了名字和参数。我们从空目录重新走一遍，每一步都能验证。

小 R：要先装一堆东西吗？

老 S：只装 Node 和 pnpm。剩下的交给两条命令：Vite 脚手架和 Tailwind 插件。

学习目标 ​

  • 用 pnpm 创建 Vite 6 + React 19 + TypeScript 工程。
  • 接入 Tailwind CSS v4 的 Vite 插件，理解为什么不需要 PostCSS 配置。
  • 配好 @/* 路径别名，让后续 shadcn CLI 能正确写入文件。
  • 用一条 pnpm build 同时完成类型检查与生产构建。

概念讲解 ​

版本基线 ​

工具版本说明
Node.js20+（推荐 22/24）Vite 6 的最低要求是 18，但 20 更稳
pnpm10+本教程使用 12.x，lockfile 为 v9
Vite6.x开发服务器与构建
React19.x函数组件 + 新 JSX 转换
TypeScript5.7strict: true
Tailwind CSS4.xCSS-first 配置，Vite 插件接入

第一步：创建工程 ​

bash
pnpm create vite my-app --template react-ts
cd my-app
pnpm install

生成的结构：

my-app/
├── index.html
├── package.json
├── tsconfig.json
├── tsconfig.app.json
├── tsconfig.node.json
├── vite.config.ts
└── src/
    ├── main.tsx
    └── App.tsx

本教程的示例为了减少文件数量，把三个 tsconfig 合并成一个，并在 include 中同时纳入 src 与 vite.config.ts。两种做法等价。

第二步：接入 Tailwind v4 ​

bash
pnpm add tailwindcss @tailwindcss/vite

修改 vite.config.ts：

ts
import path from 'node:path'
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: {
    alias: {
      '@': path.resolve(import.meta.dirname, './src'),
    },
  },
})

把 src/index.css 的全部内容替换为一行：

css
@import "tailwindcss";

然后在 main.tsx 中引入它（脚手架默认已经引入）。到这里 Tailwind 就生效了。

v4 为什么不需要 tailwind.config.js

v3 依赖 PostCSS 扫描配置，v4 改由 Vite 插件直接扫描源码，设计 token 用 CSS 的 @theme 声明。没有配置文件不是漏了，是设计如此。需要覆盖默认 token 时，在 index.css 里写 @theme { --color-brand: oklch(...); }。

第三步：配置路径别名 ​

tsconfig.json：

json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noEmit": true,
    "types": ["vite/client"],
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  },
  "include": ["src", "vite.config.ts"]
}

vite.config.ts 里的 resolve.alias 与 tsconfig.paths 必须同时配置：前者给打包器看，后者给 TypeScript 看。只配一边，要么编辑器报红，要么构建失败。

第四步：验证 ​

bash
pnpm dev     # 打开终端输出的地址
pnpm build   # tsc --noEmit && vite build

build 脚本建议写成 tsc --noEmit && vite build：先做类型检查，再打包。CI 里一条命令就能挡住类型错误。

pnpm 12 的构建脚本批准 ​

pnpm 10+ 默认阻止依赖执行构建脚本。Vite 依赖的 esbuild 需要构建，否则会报：

Ignored build scripts: esbuild.

在项目根放一个 pnpm-workspace.yaml：

yaml
allowBuilds:
  esbuild: true

本仓库的每个 examples/* 都自带这个文件，作为独立 workspace 根，避免被文档工程的依赖树接管。

可运行示例 ​

完整工程见 examples/01-hello。

bash
cd examples/01-hello
pnpm install
pnpm dev
pnpm build

页面上的「验证清单」对应四件事：

tsx
<Dialog.Root>
  <Dialog.Trigger asChild>
    <button className="rounded-lg bg-slate-900 px-4 py-2 text-white">
      打开原生 Dialog
    </button>
  </Dialog.Trigger>
  {/* Portal + Overlay + Content 全部由 className 控制外观 */}
</Dialog.Root>

如果按钮有样式、弹窗能被 Esc 关闭、焦点能回到按钮，说明 Tailwind 与 Radix 都已正常工作。

常见坑 FAQ ​

Q：@tailwind base; @tailwind components; @tailwind utilities; 还要写吗？

不要。那是 v3 语法。v4 只保留一行 @import "tailwindcss";。

Q：import.meta.dirname 在 Vite 配置里报错？

它要求 Node 20.11+ 与 ESM。旧环境改用 path.dirname(fileURLToPath(import.meta.url))。

Q：pnpm 安装后 esbuild 没构建，dev 起不来？

在项目根加 pnpm-workspace.yaml 并写 allowBuilds: esbuild: true，然后重新 pnpm install。

Q：Node 18 可以吗？

Vite 6 官方要求 18+，但 React 19、Tailwind v4 与部分工具链已把 20 作为事实基线。直接用 20/22 LTS，少踩坑。

Q：为什么示例把 vite.config.ts 放进 tsconfig 的 include？

为了让编辑器对配置文件的类型也做检查，同时 tsc --noEmit 会覆盖它。注意需要安装 @types/node。

练习与延伸 ​

  1. 从空目录重新搭一遍，记录每一步的命令与产物。
  2. 把 index.css 改成两行：@import "tailwindcss"; 加一行自定义 @theme，观察任意值类与自定义 token 的差别。
  3. 故意删掉 vite.config.ts 的 alias，确认编辑器与构建分别报什么错。
