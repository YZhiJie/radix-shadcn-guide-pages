1.3 第一个页面：用 shadcn CLI 生成组件 ​

漫画引入 ​

小 R：环境好了，我想写个卡片页面。是不是要先把 Button 的 padding、hover、focus 全写一遍？

老 S：不用。跑两条 CLI 命令，button 和 card 的源码就出现在你项目的 src/components/ui/ 里。

小 R：生成完还能改吗？会不会下次升级被覆盖？

老 S：代码复制进来就是你的。CLI 只在你主动执行 add 时写文件，不会背着你升级。

学习目标 ​

  • 掌握 shadcn init 与 shadcn add 的用法与产物。
  • 读懂 components.json 里每一项配置的作用。
  • 理解生成的组件源码如何组合 Radix 原语与 Tailwind token。
  • 能写出一个由 Card、Button 拼成的完整页面，并通过类型检查。

概念讲解 ​

在已有工程里初始化 ​

shadcn CLI 4.x 不再负责脚手架。先有 Vite 工程（上一章），再在项目根执行：

bash
pnpm dlx shadcn@latest init -b radix -p nova
  • -b radix：组件基座使用 Radix 原语（另一个选项是 Base UI）。
  • -p nova：预设主题。4.x 支持 nova、vega、maia、lyra、mira、luma、sera、rhea 等预设。

不要用 -t vite 脚手架

shadcn init -t vite 会尝试 git clone 模板仓库。在受限网络或代理失效的环境下会直接失败。正确顺序是：自己用 Vite 建工程 → 在目录内 init。

初始化会改动这些文件：

文件变化
components.json新增 CLI 配置档案
src/index.css写入 CSS variables、@theme inline、shadcn/tailwind.css 引入
src/lib/utils.ts新增 cn 导出
package.json补齐 radix-ui、cn、cva、lucide-react、tw-animate-css 等依赖
tsconfig.json / vite.config.ts若未配置别名，会尝试补 @/*

添加组件 ​

bash
pnpm dlx shadcn@latest add button card
pnpm dlx shadcn@latest add dialog popover tooltip

每次 add 都是「下载源码 → 写入 src/components/ui/ → 补依赖」。同一个组件重复添加会跳过相同文件，加 --overwrite 才覆盖。

components.json 逐项解读 ​

json
{
  "style": "radix-nova",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/index.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "iconLibrary": "lucide",
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  }
}
  • style：预设样式（基座 + 主题组合），决定类名风格。
  • rsc：是否输出 React Server Components 指令。纯 Vite 项目为 false。
  • tailwind.css：设计 token 写入哪个 CSS 文件。
  • cssVariables：用 CSS 变量承载颜色。设为 false 时组件里会出现具体色值，主题切换会失效。
  • aliases：CLI 写文件与生成 import 时使用的路径。必须与 tsconfig.paths 一致，否则生成代码引用不到。

生成的 Button 长什么样 ​

examples/02-first-page/src/components/ui/button.tsx 的核心：

tsx
import { cva, type VariantProps } from "class-variance-authority"
import { cn } from "cn"
import { Slot } from "radix-ui"

const buttonVariants = cva(
  "inline-flex items-center justify-center rounded-lg text-sm font-medium ...",
  {
    variants: {
      variant: {
        default: "bg-primary text-primary-foreground hover:bg-primary/80",
        outline: "border-border bg-background hover:bg-muted",
        // ...
      },
      size: { default: "h-8 px-2.5", sm: "h-7 px-2.5", icon: "size-8" },
    },
    defaultVariants: { variant: "default", size: "default" },
  }
)

function Button({ className, variant, size, asChild = false, ...props }) {
  const Comp = asChild ? Slot.Root : "button"
  return (
    <Comp
      data-slot="button"
      className={cn(buttonVariants({ variant, size, className }))}
      {...props}
    />
  )
}

三个要点：

  1. cva 定义变体矩阵：variant 与 size 组合出有限集合，避免到处写条件类名。
  2. cn 合并类名：后传入的 className 可以覆盖默认值，tailwind-merge 会处理冲突。
  3. asChild + Slot：让 Button 把样式与行为交给子元素（例如把 <a> 渲染成按钮外观）。

设计 token 进入 CSS ​

src/index.css 同时包含三层：

css
@import "tailwindcss";
@import "tw-animate-css";
@import "shadcn/tailwind.css";
@import "@fontsource-variable/geist";

@custom-variant dark (&:is(.dark *));

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  /* ...把 CSS 变量映射成 Tailwind 颜色工具类 */
}

:root {
  --background: oklch(1 0 0);
  --primary: oklch(0.205 0 0);
  /* ... */
}

.dark {
  --background: oklch(0.145 0 0);
  --primary: oklch(0.922 0 0);
}

@theme inline 让 bg-background、text-primary 这类工具类指向变量；变量换值，整站换肤。下一章会深入拆解。

可运行示例 ​

完整工程见 examples/02-first-page。

bash
cd examples/02-first-page
pnpm install
pnpm dev
pnpm build

页面由两层 Card 与一组 Button 组成：

tsx
import { ArrowRight, Sparkles } from "lucide-react"
import { Button } from "@/components/ui/button"
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card"

<Card>
  <CardHeader>
    <CardTitle>组件来自「复制」，而不是「安装」</CardTitle>
  </CardHeader>
  <CardContent className="flex flex-wrap gap-3">
    <Button><Sparkles />默认按钮</Button>
    <Button variant="secondary">次要按钮</Button>
    <Button variant="outline">描边按钮</Button>
    <Button variant="destructive">危险按钮</Button>
    <Button size="sm">小号</Button>
    <Button variant="link">链接按钮<ArrowRight data-icon="inline-end" /></Button>
  </CardContent>
</Card>

观察这几件事：

  1. variant 切换时颜色来自 --primary、--secondary、--destructive 等 token。
  2. 图标自动继承尺寸与颜色，data-icon="inline-end" 让按钮自动调整右内边距。
  3. 组件目录里没有任何 .css 文件，所有样式都是工具类。

常见坑 FAQ ​

Q：init 卡在「Checking registry」怎么办？

CLI 需要访问 registry。公司网络下设置 HTTPS_PROXY，或确认 NO_PROXY 没有把 registry 排除。代理失效时先修网络，不要反复重试。

Q：生成的组件里有 "use client"，Vite 项目需要吗？

不需要，但无害。它是给 Next.js 的 Server Components 用的标记，Vite 会当作普通字符串保留。

Q：可以直接改 src/components/ui/button.tsx 吗？

可以，这就是设计意图。但建议先看清楚 cva 的变体矩阵，优先加 variant 而不是在业务里堆 className。

Q：以后想升级 shadcn 组件怎么办？

重新跑 add 并对比 diff；或用 --overwrite 覆盖后重新应用你的定制。把它当模板，不当依赖。

Q：为什么 cn 是从 cn 包导入，而不是 @/lib/utils？

这是 4.x 的变化：cn 成为独立包，src/lib/utils.ts 只是转导出。旧教程里手写 clsx + tailwind-merge 也能工作，但不必再自己维护。

练习与延伸 ​

  1. 给 Button 新增一个 variant: "success"，颜色用 bg-emerald-600 text-white，并在页面上验证。
  2. 把 components.json 的 cssVariables 改成 false，重新 add button --overwrite，对比生成的类名差异（完成后改回）。
  3. 用 Card + Button + lucide-react 拼一个属于你的登录卡片页面。
